# 작업 흐름 선택 지도

실제 과제와 이미 확인한 상태에 맞춰 합치거나 생략한다. 다음 9상태는 9번의 요청·9개 문서·9개 Skill을 요구하지 않는다. 사용자에게 진행표를 매번 채우게 하지 않는다.

| 상태 | 할 일 | 넘어갈 근거 / 요청 가이드 번호 |
|---|---|---|
| 환경·규정 | 과제 루트, 원문, 입력, 제출 조건, 허용 도구와 실제 시간 확인 | 확인·미확인 구분 / 01 |
| 유형·위험 | 실제 출력과 중요한 실패를 골라 필요한 경로 선택 | 불필요한 API·UI·도구 제외 / 02, 21–31 |
| 요구·질문 | 필수·선택·제외와 출처, 결과를 바꾸는 업무 질문과 답 반영 | 질문→관련 요구·기대값 연결 / 03–04 |
| 계획·승인 | 최소 완결 흐름, 순서·검증·대안·제외를 PLAN에 기록 | 사용자 최초 승인; 기존 승인 재사용 / 05 |
| 첫 완결 결과 | 대표 입력에서 실제 사용 가능한 출력까지 연결 | 실제 파일·실행; health/mock만으로 대체 안 함 / 06 |
| 필수 구현·검증 | 작은 요구 단위로 구현하고 중요한 정상·예외·독립 기대값 확인 | 요구→파일→실제 근거, 미완료 구분 / 07–08 |
| 위험 교차 점검 | 누락·잘못된 기준·권한·중복 실행 등 중요한 부분 검토 | 발견·반영/기각·관련 재검증; 필요할 때만 / 11 |
| 마무리·이해 | 현재 저장본·필수 출력·실행법·한계·사람 확인 연결 | 최종 대조와 본인 설명; AI 허용 단계에서만 / 14–15 |
| 전달·종료 | 실제 제출 절차와 수신·확정 상태를 구분 | 사용자/플랫폼 확인; AI 금지 단계 진입 시 중단 |

## 조건이 생겼을 때만 갈래 선택

- **새 답·입력·규정:** 영향받는 요구·기대값·계획과 검사만 갱신한다. 중요한 범위 변경은 사용자 결정, 바뀐 대상의 과거 검사는 STALE로 구분한다. 요청 04·09.
- **실패:** 실제 관찰→검사할 가설→국소 수정→같은 유효 기준으로 재검증한다. 가설 수를 고정하지 않고 동일 실패를 반복하지 않는다. 선택 도구의 부재와 필수 결함을 구별한다. 요청 10.
- **세션 전환·압축:** 실제 전환 때만 현재 상태를 인계한다. PLAN 인계 절이 충분하면 재사용하고, 다른 세션에 전달할 짧은 파일이 유용하면 HANDOFF를 만든다. 요청 12–13.
- **복합 검토:** 이미 지원·허용된 읽기 전용 독립 검토가 유용할 때만 사용한다. 미지원·금지·오류이면 순차 검토와 직접 검사로 전환한다. [기존 리뷰 조건](parallel-review.md).
- **남은 시간 감소:** 선택 작업을 줄이고 필수 결과·치명적 오류·최종 검증·전달에 집중한다. 실제 시간과 지침을 따르며 고정 시간표를 만들지 않는다.

작은 문서 과제에 API나 UI를 붙이지 않는다. 이미 실행되는 프로젝트는 기존 흐름을 재사용한다. 코드 없는 작업은 원문→분석→제출 파일의 완결 흐름으로 적용한다. 상세 요청은 [프롬프트 가이드](prompt-guide.md)의 관련 절만 읽는다.
