# moonskill2 — Work Session

계획 검토 후 작은 단위로 작업하고, 실제 판단과 검증 근거를 남기는 가벼운 Codex 작업 지침과 Skills입니다.

## 구성

- 진입 Skill 하나: `work-session`
- 계획 검토·UI·API·오류 진단·검증을 위한 보조 Skills 7개
- 필요할 때만 읽는 조건부 도구·질문 전략 지침
- 과제 유형·주요 위험, 선택적 독립 리뷰, 중단 후 재개 지침
- `PLAN.md`, `DECISIONS.md` 작성용 템플릿
- 사용자 전용 [프롬프트 참고서](PROMPTS.md): Skill 폴더 밖에서 IDE로 직접 열어 봅니다.
- 기존 지침을 보존하는 [AGENTS 진입 안내](AGENTS.md)
- 실제 전환 때만 쓰는 선택형 HANDOFF 양식과 검증 상태 안내

별도 실행 엔진, 훅, MCP, API 키, 모델 변경, 전역 설정이 필요하지 않습니다. 특정 언어·웹사이트·API·데이터 형식을 전제하지 않습니다. Skill은 Codex에 제공하는 작업 지침이며, 권한을 부여하거나 동작을 강제로 차단하는 프로그램은 아닙니다. 보조 Skills는 함께 설치하지만 필요한 작업에서만 지침을 읽고 적용합니다.

## 기본 흐름

자료·현재 상태 확인 → 중요한 빈칸과 담당자 질문 초안 정리 → 전달받은 답 반영·PLAN 검토 요청 → 사용자 승인 → 작은 작업 하나 구현·검증 → PLAN 갱신 → 다음 작업 → 최종 요구 충족 확인. 질문이 불필요하면 질문 단계를 건너뜁니다.

- 최초 계획 승인 전에는 자료 확인과 계획 문서 작성만 합니다.
- 승인된 범위의 통상 작업마다 다시 승인을 요구하지 않습니다.
- 선택 도구가 없으면 이유와 대안을 한 번 기록하고 진행합니다.
- 필수 요구가 막혔으면 차단 상태로 남깁니다. 생략을 성공으로 표시하지 않습니다.
- 기록은 중요한 변경·결정·검증에만 남깁니다. 모든 대화와 명령을 복제하지 않습니다.
- 단계가 끝나면 **한 것 / 근거 / 사용자가 정할 것 / 다음 할 것**을 짧게 보고합니다. 근거는 문서 확인과 실제 실행 결과를 구분하며, 결정할 것이 없으면 없다고 표시합니다.
- 사용자 보고·질문 초안·PLAN·DECISIONS는 한국어로 작성합니다. 코드 식별자·명령·경로·API 필드·원문 인용 등 정확성이 필요한 표기는 유지하고 필요한 설명을 한국어로 덧붙입니다.
- 과제에 맞는 작업 경로와 중요한 실패 위험을 골라 적용합니다. 정해진 여러 단계를 전부 실행하거나 문서를 늘리는 방식이 아닙니다.
- 독립 리뷰가 유용하고 제공 도구가 지원할 때만 읽기 전용 검토자를 활용합니다. 도구 부재·권한 제한·오류가 있으면 한 번 기록하고 직접 검증 또는 순차 검토로 진행합니다. 이를 위해 새 에이전트 환경을 구축하지 않습니다.

## 설치

공개 저장소: `https://github.com/moon-gi-jeon/moonskill2`

1. 이 README와 `manifest.json`을 읽고 가져올 파일을 확인합니다.
2. 현재 작업 프로젝트의 실제 Skill 발견 경로를 확인합니다. 표준 프로젝트 경로는 `.agents/skills`입니다.
3. 기본 설치는 `skills/` 아래 8개 Skill 폴더 전체를 발견 경로 아래에 복사하는 방식입니다. 기존 동명 Skill은 해시가 같으면 유지합니다. 이 패키지의 수정되지 않은 구버전으로 확인되고 최신 버전 설치 요청이 있으면 해당 파일을 갱신합니다. 다른 출처이거나 사용자 수정 여부가 불명확하면 기존 파일을 보존하고 차이와 교체 선택을 알립니다. `work-session`만 요청하면 해당 폴더만 설치할 수 있습니다. 프로젝트 README, 설정·Git 상태는 자동 변경하지 않습니다. AGENTS 진입 안내는 아래의 보존·충돌 확인 절차로 적용합니다.
4. manifest의 SHA-256과 설치 파일을 대조합니다. 가져온 원본 참고 폴더의 `manifest.json`, `SOURCES.md`, 라이선스·고지를 보존하고 그 위치를 설치 보고에 남깁니다. 이 참고 폴더를 공식 제출물에 포함할지는 과제의 제출 조건을 따릅니다.
5. 사용자 참고서 `PROMPTS.md`를 Skill 폴더 밖의 `docs/moonskill2/PROMPTS.md`에 복사하거나, 과제에서 허용하는 동등한 별도 참고 위치에 둡니다. 기존 파일이 다르면 보존하고 충돌 없는 위치를 선택합니다. 실제 경로를 사용자에게 알려 IDE에서 직접 열게 합니다. 이 문서를 자동 참조·Skill 발견 대상으로 등록하지 않습니다.
6. 적용한 AGENTS와 설치된 work-session을 현재 세션에서 명시적으로 읽습니다. **파일 설치·해시 일치 / Skill 목록 인식 / 실제 호출·지침 적용**을 나누어 보고합니다. 복사만으로 현재 세션의 자동 재로딩을 가정하지 않습니다.

### AGENTS 진입 안내 적용

하네스 설치와 진입 안내 적용을 요청한 경우, 실제 과제 루트와 기존 `AGENTS.md`를 먼저 읽습니다. 기존 파일이 없으면 이 저장소의 `AGENTS.md`를 배치하고 실제 Skill 경로를 확인합니다. 이미 있으면 **덮어쓰거나 원문 전체를 덧붙이지 않습니다.** 기존 안내로 충분하면 유지하고, 연결이 없을 때에만 충돌 없는 짧은 포인터를 식별 가능한 블록으로 추가합니다. 예시:

```markdown
<!-- work-session:begin -->
허용된 작업에 설치된 `.agents/skills/work-session/SKILL.md`를 적용한다.
재개 시 기존 PLAN·DECISIONS와 실제 파일, 인계가 있으면 그 요약을 대조한다.
사용자용 프롬프트 참고서는 자동으로 읽거나 양식을 추천·출력하지 않는다. 실제 과제의 질문·계획·결과를 보고한다.
기존 과제 지침과 승인 범위가 우선이며, 충돌하는 부분은 적용하지 않는다.
<!-- work-session:end -->
```

동일 블록을 중복 추가하지 않습니다. 기존 work-session 블록에 옛 가이드 자동 참조 문구가 있으면 해당 블록만 갱신하고 다른 과제 지침은 보존합니다. 다른 발견 경로는 실제 경로로 바꿉니다. 과제 규칙이 추가·변경을 금지하거나 의미 충돌이 있으면 기존 파일을 유지하고 `$work-session` 직접 호출로 진행하며 그 사실을 보고합니다. 설치·규칙 병합·목록 인식·실제 호출은 따로 확인합니다. 새 세션에서 파일이 실제로 읽혔다는 확인 없이 자동 적용을 보장하지 않습니다.

설치 스크립트는 포함하지 않습니다. 허용된 공개 HTTPS 다운로드 또는 clone으로 소스를 가져와 필요한 폴더만 복사하는 방식입니다. 목록 갱신이 안 되면 해당 Codex의 안내를 확인합니다. 업데이트나 권한 우회로 해결하지 않습니다.

목록에 보이지 않을 때에는 파일을 직접 읽고 같은 작업 규칙을 적용할 수 있지만, 이를 `$` 호출 성공으로 보고하지 않습니다.

## 사용할 때

설치·인식이 확인되면 다음처럼 요청합니다.

```text
$work-session 포함된 Skills를 필요한 단계에만 활용하고, 과제와 자료를 확인하여 계획부터 작성해줘. 검토 후 승인하면 작은 단위로 진행해줘.
```

계획을 읽고 수정할 점을 말하거나 승인하면 됩니다. 이후에는 자연어로 반론·요구 변경·다음 작업을 요청할 수 있습니다. 다시 시작할 때에는 기존 계획·결정·인계가 있으면 해당 기록과 실제 파일을 대조하여 이어갑니다. 사용자는 IDE의 `docs/moonskill2/PROMPTS.md` 또는 설치 시 안내받은 위치를 직접 열어 상황 하나를 고릅니다. Codex에 가이드 전체나 양식을 출력시킬 필요는 없습니다.

### 사용자의 실제 역할

1. 시작 시 과제 자료와 목표를 알려줍니다. 이미 문서에 있는 기술 조건을 다시 외워서 입력할 필요는 없습니다.
2. AI가 만든 담당자 질문 초안을 필요한 대상에게 전달하고, 받은 답을 그대로 알려줍니다. AI는 답으로 바뀐 요구·가정·계획·검증을 갱신합니다.
3. 제시된 최소 흐름·단계·완료 기준·제외 범위를 읽고 수정하거나 승인합니다.
4. 이후에는 의견·반론·관찰한 오류를 자연어로 말합니다. 중요한 변경만 다시 판단하고, 승인 범위의 통상 작업은 계속 진행됩니다.
5. 필요한 화면 동작과 최종 저장·제출 상태는 직접 확인합니다. 설명이 필요하면 주요 흐름·선택 이유·한계를 쉬운 말로 요청합니다.

독립 리뷰의 예: 요구 누락과 중요한 오류를 다른 관점에서 확인할 가치가 있을 때 사용합니다. 작은 과제는 한 세션의 직접 검증으로 충분할 수 있습니다. 검토자의 PASS, 같은 세션의 재검토, 실제 기능 검사 결과를 구분합니다.

## 다른 Skills와 함께 쓰기

| 포함된 Skill | 적용할 때 |
|---|---|
| `grill-me` → `grilling` | 계획의 중요한 가정·대안·빈틈 점검. 둘은 연결된 진입점과 본체이므로 중복 인터뷰하지 않음 |
| `frontend-design` | 실제 화면·사용자 인터페이스를 구현하거나 개선할 때 |
| `api-and-interface-design` | 실제 API·인터페이스 계약을 만들거나 변경할 때 |
| `api-tester` | 실제 제공·구현 API를 허용된 HTTP 방식으로 검사할 때 |
| `diagnosing-bugs` | 관찰된 중요한 오류의 원인을 진단할 때 |
| `verification-before-completion` | 최종 완료 주장 전에 실제 근거를 점검할 때 |

다른 하네스의 AGENTS·WORKLOG·상태 엔진까지 함께 적용하지 않습니다. 이미 존재하는 과제 지침과 동명 Skill은 출처·적용 범위를 확인하고 충돌하는 외부 규칙만 제외합니다. 전체를 한꺼번에 읽거나 순서대로 실행하지 않습니다. `work-session`이 해당 단계에서 필요한 Skill의 지침만 참조합니다. 이 연결은 별도 프로세스를 자동 실행하는 기능이 아닙니다. 하위 Skill의 일반적인 자동 실행 권고가 이 작업의 계획 승인 조건을 대신하지 않습니다. 보조 Skill이 없는 부분 설치에서도 기본 흐름은 직접 수행할 수 있습니다.

## 문서와 제출

기존 과제 문서와 제출 조건을 먼저 따릅니다. 같은 역할의 문서가 있으면 재사용하며, 템플릿 때문에 새 파일을 강제로 만들지 않습니다. 공식 산출물과 작업 메모는 구별합니다. 파일 이름·문서 수·Skill 수 자체가 결과의 품질을 증명하지는 않습니다.

- **PLAN:** 목표, 요구 ID·출처·기대 동작, 담당자 질문 초안·상태·실제 답변, 가정, 구현 순서, 검증 방법·실제 근거, 현재 상태와 다음 작업을 통합합니다. 새 정보가 들어오면 영향받은 항목만 갱신합니다.
- **DECISIONS:** 중요한 선택·이유·버린 대안·한계·변경 이력을 기록합니다. 답변 원문 전체를 중복 보관하지 않습니다.

별도 workflow/worklog 문서를 만들지 않습니다. PLAN 전체를 매번 재작성하지 않고 바뀐 행과 짧은 진행 근거만 수정합니다. 담당자 질문은 실제 업무 흐름·목표·제약·성공 기준·자료 의미 중 구현에 영향을 주는 빈칸에서 도출합니다. 사용자가 질문을 전달하고 받은 답을 알려주면 Codex가 확인된 요구·가정·계획·검증 기준을 연결하여 갱신합니다.

실제 전환 때 다른 세션에 건넬 파일이 유용하면 짧은 `HANDOFF.md`를 만들 수 있습니다. [양식](skills/work-session/assets/HANDOFF.template.md)의 관련 항목만 쓰고 PLAN에 그 경로를 연결합니다. HANDOFF는 현재 정본을 가리키는 스냅샷이며 PLAN·DECISIONS와 같은 상태를 두 곳에서 따로 갱신하지 않습니다.

실제 실행·수동 관찰·미검증을 구분하고, 최종 제출이나 외부 게시에는 해당 작업의 승인·절차를 따릅니다.

## 범위와 라이선스

`work-session` 지침과 템플릿은 독자 작성했으며 MIT 라이선스로 제공합니다. 보조 Skills는 각 원저작 출처의 지침을 용도에 맞게 수정한 버전입니다. 원본 라이선스와 수정 이력을 유지하며, 루트 MIT는 제3자 라이선스를 대체하지 않습니다. `THIRD_PARTY_NOTICES.md`, `SOURCES.md`, `manifest.json`을 참조하세요.

변경 내용은 `CHANGELOG.md`에 기록합니다. 지침에 따른 실제 결과·시간·사용량은 작업과 실행 환경에 따라 달라집니다.

## 1.2.0에서 갱신할 때

1.2.0에서 설치한 work-session의 `references/prompt-guide.md`는 새 버전에 포함되지 않습니다. 이전 manifest 해시와 일치하는 패키지 소유 파일로 확인되면 사용자용 참고서가 새 위치에 정상 배치된 뒤 그 옛 파일만 제거합니다. 사용자가 수정했거나 출처가 불명확하면 삭제하지 않고 별도 사용자 참고 위치에 보존합니다. Skill 디렉터리 전체나 기존 과제 파일을 지우지 않습니다. 이전 AGENTS 연결 블록의 가이드 읽기 지시도 현재 안내로 갱신합니다.
